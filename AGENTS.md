# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

Live Spec is a Tauri v2 desktop app for writing a spec against a codebase. The user types the spec on the left; when they pause, an LLM that has read the selected project streams review notes into the right-hand panel under the sections the tab has chosen from a five-entry catalogue: **Intent, Conflicts (with code), Gaps, Ambiguities, Questions**. The goal is a spec an AI coding agent can implement without further discovery or guessing. The model comes from one of three providers: the user's installed Claude Code CLI (default), the Anthropic API (key in the OS keychain), or a local GGUF model served by a llama.cpp runtime the app downloads on demand.

## Commands

Prerequisites: Rust stable, the Tauri v2 system prerequisites, and **Node 20.19+ or 22.12+**. Vite 7 requires that: on Node 20.11, `vite` crashes with `crypto.hash is not a function`. Typecheck and vitest still pass on older Node, which hides the problem until you start the app.

```bash
npm install
npm run tauri dev        # the app: Vite on :1420 (strictPort) + the Rust shell
npm run tauri build      # platform installer
npm run typecheck        # tsc --noEmit
npm test                 # vitest
npx vitest run src/lib/sections.test.ts -t "partial streams"   # one frontend test

cargo test -p livespec-core                    # Rust unit tests
cargo test -p livespec-core retrieve::tests    # filter by module/test path
cargo test -p livespec-core -- --ignored       # network: downloads and runs the real llama.cpp build
cargo clippy --workspace --all-targets               # currently warning-free
cargo check -p livespec                              # Tauri shell (package `livespec`, lib `livespec_lib`)

# What retrieval would pick for a draft; use it when tuning terms/retrieve
cargo run -p livespec-core --example probe -- <project-dir> "<draft text>"
```

- `npm run dev` starts Vite alone. Every `invoke` fails outside the Tauri webview, so UI work needs `npm run tauri dev`.
- `src-tauri` has no tests. Logic you want covered belongs in `livespec-core`.
- There is no rustfmt config. The Rust is hand-wrapped at about 120 columns, and `cargo fmt` rewrites about 80 hunks, so don't run it across the repo; match the surrounding style instead. There is no ESLint or Prettier either.

## Architecture

| Layer | Path | Role |
|---|---|---|
| UI | `src/` (React 19 + Vite, no state library) | Sidebar of tabs, draft, notes, brief drawer, settings. This window's tabs live in `src/lib/tabs.ts` and its projects' summaries, instructions and brief builds in `src/lib/projects.ts` (module stores read with `useSyncExternalStore`); each tab's live analysis is a `TabSession` (`src/lib/tabSession.ts`) outside React. `App.tsx` holds only settings and which drawer is open |
| Shell | `src-tauri/` | IPC commands, `AppState`, settings → provider resolution, keychain. Deliberately thin |
| Core | `crates/livespec-core/` | Scan/index/retrieve, brief cache, prompts, providers, local runtime, sessions (tabs, windows, saved analyses), the usage ledger (`usage`). **Must not depend on Tauri** |

### UI and styling

- **Tailwind v4** through `@tailwindcss/vite`. There's no `tailwind.config`; theme and tokens live in `src/styles.css`.
- **Colours are semantic tokens** (`bg-page`, `bg-panel`, `bg-subtle`, `border-line`, `text-ink`, `text-muted`, `text-faint`, `text-accent`, `text-fault`, `text-question`). They map to `--lb-*` variables that switch under `prefers-color-scheme: dark`. Use these rather than raw palette classes or `dark:` variants. The note colours carry meaning: conflicts red, gaps blue, ambiguities and questions amber.
- **Fonts are bundled from Fontsource, never fetched**, because the app must work offline and the CSP only allows `'self'`. The user's draft is set in Literata (`font-serif`), the AI's notes and the UI in Inter (`font-sans`), and code in JetBrains Mono (`font-mono`).
- **Shared primitives** live in `src/components/ui.tsx`: `Button` (with a compact `mini` variant for sidebar rows), `Field`, `inputClass`, `Eyebrow`, `Menu` (a popup menu at a point; Esc, a click outside or the window losing focus closes it), `Select` (a select-only combobox styled like `Menu`, used instead of a native `<select>`; its list is portalled into the enclosing `<dialog>`, else `<body>`, and its Esc never closes the drawers or Settings; key handling in `src/lib/listbox.ts`), `RULE` / `RuleState`, and the `cx` class joiner. Use them instead of repeating class lists.
- **Layout:** `main` is a three-column grid, `[sidebar 248px | draft 3fr | notes minmax(320px, 2fr)]`. The draft and notes panes are flex columns with `min-h-0` and their own `overflow-y-auto`. The draft `<textarea>` fills its pane, and percentage padding centres a 40rem text column, so the textarea and the word-count footer line up. ⌘\\ hides the sidebar (`display: none`, so the grid drops to two columns). A window narrower than 1,100 px starts with it hidden, unless the user chose otherwise in that window (`readCollapsed` / `writeCollapsed` in `src/lib/tabList.ts`).
- **Rule animation:** the accent rule between the panes (`Rule` in `NotesPane.tsx`) and the 2 × 28 px rule on each sidebar tab row share the state classes in `RULE` (`ui.tsx`): solid when the notes are current, animated (`animate-fill`) while thinking, dashed when the draft has moved on, an empty track when idle (also a tab not shown since launch). `ruleState` and `statusLine` in `src/lib/tabStatus.ts` derive both from a tab's `TabView`. Under `prefers-reduced-motion` the rule is static (`motion-reduce:animate-none`, `opacity-50`), and the row's status line ("Analysing…", "Draft moved on", "Notes current", or the error in `text-fault`) carries the state. A folded project group shows the `animate-pulse-dot` dot while any of its tabs is analysing.
- **Sidebar** (`Sidebar.tsx`, `TabRow.tsx`, `ClosedTabs.tsx`): this window's tabs, grouped by project in order of first appearance (`groupTabs` in `src/lib/tabList.ts`). Tabs without a project sit under "No project", and two projects with the same folder name also show their parent folder. ⌃Tab / ⌃⇧Tab follow this visual order, not the stored list, and closing the shown tab shows the next one in it (the previous one when it was last). A tab's title is its name, else the first line of its draft, else "Untitled"; double-click or F2 renames it, and a blank name returns to the automatic title. The context menu has Rename and Close. *Recently closed (n)* is shared by every window and grouped by project; Delete asks inline ("Delete for good?"), never with `confirm()`. The footer shows draft-save errors, "Couldn't read a tab; kept it as <file>.bad" notices, an optional `footer` node and the provider label.
- **Sections picker** (`SectionsPicker` in `NotesPane.tsx`): `Sections ▾` opens the shared `Menu` with one checkbox item per catalogue entry (`MenuItem.checked`, `keepOpen`; only a menu with toggles gets the mark column); the last checked one is disabled. `tabs.setSections` saves through `set_tab_sections`, then `TabSession.setSections` re-runs the shown tab after a pause (a hidden one when shown). `create_tab` takes the shown tab's sections when the new tab is on the same project. *Copy spec* in the draft footer goes through `copyText` (`src/lib/clipboard.ts`), which never throws.
- **Tab state lives outside React.** `src/lib/tabs.ts` is this window's store (`useSyncExternalStore`, like `downloads.ts`): the `WindowView` from `list_workspace`, the shown tab, and one `TabSession` (`src/lib/tabSession.ts`) per tab shown since launch, so a hidden tab keeps its pause timer and its run. It refetches on every `workspace-changed`. Draft edits save through one `createSaver` keyed by tab id (500 ms), flushed on a switch, before closing a tab and on `pagehide`. `src/lib/projects.ts` caches each project's summary, instructions and brief build for the window, and hands each project's `analysisContextKey` to its tabs (`tabs.setContext`) only once both the summary and the instructions have loaded: a key computed earlier (`root|0|`) would differ from the saved notes' and start a run at launch. A context change on a hidden tab only sets `contextDirty`, and `activate()` runs it when the tab is shown, so a rebuilt brief or edited instructions re-run only the tab on screen.
- **History:** each tab keeps its last 5 analyses. `TabSession.view(index)` browses them (`viewing` 0 is the live state, k ≥ 1 is `history[k]`). `done` refetches the history with `get_tab`, and `started` goes back to the latest. `NotesPane` shows `‹ 2 of 5 ›` and the time (`historyPosition` and `snapshotTime` in `src/lib/history.ts`; hidden with fewer than two), and renders an older analysis read-only through `snapshotAnalysis`, under "Notes on an earlier draft.", with its draft behind *Show that draft*.
- **Shortcuts** go through `useActions` (`src/lib/actions.ts`), one `keydown` listener per window: ⌘T new tab on the shown tab's project, ⌘O open a project, ⌘⇧T reopen the last closed tab, ⌘W close the tab, ⌃Tab / ⌃⇧Tab next and previous tab, ⌘\\ sidebar, ⌘, settings. Ctrl replaces ⌘ on Windows and Linux, and on macOS Ctrl+letter keeps its text-editing meaning (⌃T transposes). A key runs only the handlers `App.tsx` passes, calls `preventDefault()` only then, and does nothing while a modal `<dialog>` is open.
- **Settings** is a native `<dialog>` opened with `showModal()`, which gives focus trapping, Esc and `::backdrop` for free. Esc for the brief and instructions drawers is handled in `App.tsx`; only one drawer is open at a time.

### Live analysis flow

1. Each tab's `TabSession` (`src/lib/tabSession.ts`) waits for a typing pause (`debounceMs`, default 1200), whether or not the tab is shown. It needs at least 24 characters after whitespace normalization and skips the call if the normalized draft hasn't changed. Its context key (`analysisContextKey` in `src/lib/instructions.ts`: the root, the brief's `createdAt` and the session instructions) changes when the project, brief or instructions do. Then the shown tab re-reads the same draft without the gate, and a hidden tab waits until it's shown. Every `analyze` call carries the tab id, the current instructions, the tab's section ids (`Tab.sections`; empty is the default set) and the context key, which the saved snapshot keeps. A tab's key is its project's key plus `|<ids>` only when the sections differ from the default (`tabContextKey`), so tabs saved before the field existed keep their key. Relaunching starts no run by itself: a restored tab whose draft matches its latest analysis doesn't, and the first context a tab with no saved analysis receives isn't a change. A project that can't be read hands its tabs only the instructions (`setContext(null, …)`), so they keep the context their saved notes ran with.
2. `analyze(tabId, draft, previousDraft, instructions, context)` (`src-tauri/src/commands.rs`) checks that the tab is open (`SessionStore::open_tab_root`, else "This tab was closed."), then returns immediately after spawning a task into `AppState.analyses`, keyed by tab id. `replace_task` aborts only that tab's previous task, so tabs analyse in parallel, and dropping that future kills its `claude` children (`kill_on_drop`). `cancel_analysis(tabId)` and `close_tab` abort it too. The task takes the index and brief from the registry entry for the tab's root (`AppState.projects`, scanned on first use); a tab with no project, or whose folder can't be read, runs without code context.
3. The task resolves a provider at `Tier::Fast` (`src-tauri/src/provider.rs`), then runs `analysis::pre_phase`. The Jev gate ("did the idea change since `previousDraft`?") and the Jev rerank (scores the 20-snippet keyword shortlist and keeps the best 3 or 5) run concurrently under `PRE_BUDGET` (1.5 s). A confident "unchanged" emits `skipped` and stops. Otherwise it emits `started`, then at most one pre-phase `notice`, resolves the tab's sections with `sections::resolve` (unknown ids dropped, nothing known → the whole catalogue), builds the prompt with `prompt::analysis_request` (which puts the session instructions in every lane's system prompt, before the rules, clipped to `min(MAX_INSTRUCTION_CHARS, budget / 10)` characters) and streams. Without Jev, or for the Local provider, or when Jev is slow or failing, this is plain keyword retrieval (`project::retrieve`).
4. After `started`, the sections are written by `Settings::effective_note_agents()` lanes at once (1 unless `agents.parallelNotes` is on, which is off by default: 4 lanes measured slower than 1 with the Claude CLI) (`prompt::section_groups(n, &chosen)`: at most `n` contiguous near-equal groups, never more than there are sections; always 1 for the Local provider). Lanes run through `agents::run_limited`, so dropping the task cancels every `claude` child. Every lane, brief explorer and brief merge calls the provider through `usage::metered`, which creates a `usage::Meter` right before `provider.stream` (so a run cancelled during the pre-phase records nothing) and records the call's usage, or an estimate when it was cut short or reported none. Every chunk is `text { text, lane }`; `done { text, partial }` carries the lanes joined in lane order (`analysis::merge_lanes` keeps only each lane's own sections), and any missing sections become one `notice` with `partial: true` (the UI offers "Try again", and partial notes never become the gate's comparison point). A failed fact-check is `checksStopped`, distinct from other notices. The fact-check starts when the lane carrying Conflicts finishes (no `checking` event when Conflicts isn't chosen) (a oneshot from that lane), concurrently with the other lanes; `done` never waits for it. Events: `text`, `activity`, `started`, `skipped`, `notice`, `checking`, `check`, `done`, `error`, `progress`. Before `done` is sent, the task saves the run to the tab's history (`sessions::Recorder`): the text, `partial`, the notices so far, and any checks that arrived first. Later checks, notices and `checksStopped` update that snapshot (`update_snapshot`). Skips and errors save nothing; a save that fails becomes one notice ("Couldn't save these notes: …") and never fails the analysis.
5. `src/lib/sections.ts` splits the streamed Markdown into the chosen sections (plus the old build's Directions, display-only), and `MiniMarkdown` renders them.

Downloads (`install_runtime`, `download_model`) follow the same pattern: spawn, keep the handle in an `AppState` slot, stream over a Channel, then send a final `done` or `error`. So does `build_brief(root)` (`Tier::Deep`), with one build per project: `AppState.brief_tasks` is keyed by root, and a request for a root whose build is still running returns at once. Every window receives `brief-status { root, state: building | done | error, message }`; only the window that started the build gets the live text over its Channel. On success the task saves the brief, rescans the project into the registry, then emits `done`, and each window refetches `project_summary(root)`.

### Project understanding: two layers

- **Brief (once per project).** With `Settings::effective_brief_agents()` > 1 and at least 40 indexed files, `project::explore::slices` splits the indexed files into balanced slices (folders, plus root source files as single entries; root README/manifests go to the merge's overview) (a folder with more than half the bytes is split one level deeper). Explorers run at once via `agents::run_limited`: with Claude CLI each is `claude -p` with read-only tools and 20 turns, told "Explore only: <prefixes>"; with the API each gets `digest::build_slice`. Their activity streams as `activity { lane: k }` ("Agent k" in the drawer); their own text isn't shown. One merge call (no tools) gets the notes, `digest::overview` and an `<unmapped>` list of failed slices, and streams the brief in today's format as lane 0. With one slice (small repo, 1 agent, Local, or `agents.parallelBrief: false`, the default) it's the single explorer as before. Briefs are cached at `<app_data>/briefs/<fnv(root)>.json` and marked stale when the project fingerprint changes; `source` notes the agent count.
- **Retrieval (every pause).** TF-IDF over identifier terms, with no embeddings. `project/terms.rs` splits camelCase and snake_case, folds plurals, and drops stopwords. The same tokenizer runs at index time and query time, so a change there affects both. The last 400 characters of the draft are weighted 1.6×, and path matches get a bonus.
- **Loaded projects.** `AppState.projects` holds one `ProjectEntry { index, brief }` per root, so tabs on several projects analyse at once. `open_project` always rescans and replaces the entry; `project_summary` scans only a root that isn't loaded. An index keeps file contents, so after `close_tab` and `delete_tab` the shell drops every entry no open tab uses (`AppState::evict_unused_projects`).

`project::scan` honours `.gitignore` even outside git (`require_git(false)`), skips hidden files and `SKIP_DIRS`, and indexes at most 6,000 text files of 256 KB or less. The fingerprint hashes (path, size, mtime) of every non-ignored file. Persisted hashes use the in-house FNV-1a (`project::Fnv`), never `DefaultHasher`, whose output isn't stable across Rust versions.

### Providers

`llm::Provider` is a closed enum (`ClaudeCli | AnthropicApi | OpenAiCompat`) with `match` dispatch, chosen on purpose over `dyn Trait` + `async_trait`. All three take the same `ChatRequest`; providers ignore fields they can't use (`cwd`, `allow_repo_tools`).

- **`ClaudeCli`** runs the user's unmodified `claude -p --output-format stream-json --verbose --include-partial-messages` and sends the prompt on stdin to avoid argv length limits. Every run passes `--restricted` (ignores settings files, so an opened repo's hooks never run; confines file tools to the project) and `--strict-mcp-config` (no MCP servers). Tools come from an allowlist via `--tools`: none (`""`) for live analysis, which also *replaces* the system prompt (`--system-prompt`, `--max-turns 1`); `Read,Glob,Grep` for the brief, which *appends* (`--append-system-prompt`) so Claude Code keeps its own repo-exploration prompt. Never reintroduce a `--disallowedTools` denylist: new tools would slip past it. Known cost: `--restricted` also ignores the user's own settings files, so auth via `apiKeyHelper` or settings `env` no longer works (documented in the README). The replacement is `ProviderSettings::ClaudeCli { auth: apiKey }`: the keychain key reaches the child only as `ANTHROPIC_API_KEY` in its environment, never in argv, which any process can list. `--effort` is passed only when a level is set, per tier (`Effort`; `None` means the model's default). The NDJSON parser ignores unknown event types on purpose, so CLI upgrades don't break it. The final answer comes from the `result` event, which excludes the narration streamed during exploration.
- **`AnthropicApi` / `OpenAiCompat`** share `llm/sse.rs`. Its buffer is `Vec<u8>`, not `String`, because a network chunk can split a UTF-8 character. `AnthropicApi` sends `output_config.effort` only when a level is set.
- **Usage:** every provider ends a call it has usage for with `Chunk::Usage` (one per model). Claude Code's comes from `result.modelUsage` (`costUSD`; falls back to `usage` + `total_cost_usd` under the requested model, and to `usage::PRICES` when the event reports no cost) and is emitted for failed runs too, unless every count is zero; the API's from `message_start` plus the last `message_delta`, priced with `usage::PRICES`; the local server's from the final chunk, requested with `stream_options.include_usage`, at $0. The pinned `llama-server` (b11480) reports usage in that final chunk, so local runs are exact. Sinks that `match` on `Chunk` need a `Usage` arm; `usage::metered` records it and never forwards it. A call that used several models (Claude Code can) counts as one run. `Provider::model()` is the model the provider was asked for (an alias such as "haiku" for Claude Code).
- **Local:** `provider::ensure_local` starts `llama-server` in its *own* spawned task. Analysis tasks are aborted on every keystroke, and an abort must not kill a model that's halfway through loading. `AppState.local` is a `tokio::sync::Mutex` because it's held across that slow startup. Every other lock in `AppState` is `std` and must never be held across `.await`. On app exit and when leaving the local provider, the server is stopped to free RAM.
- **Budgets:** `Provider::context_budget_chars()` drives all prompt sizing: 120k characters for Claude, `context_tokens × 1.5` for local models. The brief is clipped to 3/5 of the budget and snippets get 1/4. Drafts over 12k characters keep the first 2k plus the tail.

### Jev (TypeSafe)

`livespec-core::jev` is a typed client for TypeSafe's System One API (`POST https://api.typesafe.ai/v1/systemone`): one `state`, any number of Noul/Choice questions, typed answers with probabilities. It judges; it never writes text. Choice options serialize in the order given (`jev::Options`) because Jev 1.13 can lean towards the first option.

- **Fact-check ("Checked in code"):** after `done`, `commands::analyze` takes the Conflicts section (`prompt::section_body(text, "conflicts")`) and runs `jev::check::run`. Plain code finds the evidence: backticked names and paths in each bullet, matched against the in-memory index (names found in more than a quarter of the files are too generic). Jev answers supports / contradicts / says_nothing per claim; ✓/✗ need confidence ≥ 0.8. Check events arrive after `done`, and the next keystroke aborts them with the rest of the task.
- **Key lookup** (`secrets::jev_key`): Keychain account `typesafe-api-key`, then `TYPESAFE_API_KEY` in the environment, then, in debug builds only, `TYPESAFE_API_KEY` in the repo's `.env.local` (read by `env_file::read_value`, never exported). The key never crosses IPC: the rule itself is `jev::key::pick_key` (blank values never shadow a later source); `jev_status` returns a `KeyStatus { source }` (never the key) and `set_jev_key` saves to or removes from the Keychain. Settings → Jev shows the source and greys out the switches without a key or for Local. **Never prefix it `VITE_`:** Vite reads `.env.local` too and ships `VITE_*` variables to the webview bundle.
- Jev only runs for the fact-check when `Settings::jev_check_enabled()` is true: never with the Local provider, whatever the switch says (it would send code off the machine).
- Evidence matching is by whole identifiers and whole path segments; a name found in more than `min(8, files/4)` files (at least 2) is too generic to check.
- **Gate and rerank** (`jev::gate`, `jev::rerank`, `analysis::pre_phase`): the UI sends the draft of the last *completed* analysis as `previousDraft` (skips never move it; "Try again" sends null). Gate errors mean "analyse"; rerank errors mean keyword order. Neither ever adds more than `PRE_BUDGET` before the model call. Futures awaited inside the shell's spawned task must avoid closures over borrowed arguments (`Option::filter(|_| …)`, `.map(|(i, &x)| …)`): they trip rustc's Send check ("FnOnce is not general enough").
- `Settings::jev_allowed()` is false for the Local provider; `jev_gate_enabled`, `jev_rerank_enabled` and `jev_check_enabled` all respect it.
- Parallel-notes live test (runs Claude Code, uses the subscription; prints 1-lane vs 4-lane timings per lane): `cargo test -p livespec-core --test notes_live -- --ignored --nocapture`. Phase 3 measured 4 lanes *slower* than 1 with the Claude CLI (per-call overhead dominates); see the spec's measurements.
- Parallel-brief live test (Claude Code sonnet, several minutes, uses the subscription; 1 explorer vs 4 plus merge): `cargo test -p livespec-core --test brief_live -- --ignored --nocapture`. Phase 4 measured 4 explorers + merge ≈16% *slower* than 1 explorer, so `parallelBrief` defaults to off.
- Jev failures never fail an analysis; they surface as one `notice` event. The client retries 429/503/529 twice.
- Live test against the real API (needs the key; prints latency): `cargo test -p livespec-core --test jev_live -- --ignored --nocapture`.

### Errors

`livespec_core::Error` serializes as a plain string across IPC. `Precondition` means the user must act (open a project, install Claude Code, download a model). The UI shows its message verbatim, so write it as an instruction to the user. `Provider` means the model, CLI, or network failed.

### Persistence

- Settings: `<app_config>/settings.json`, written atomically (tmp file + rename). A missing or corrupt file falls back to defaults instead of blocking startup.
- API key: OS keychain (service `app.livespec.desktop`, account `anthropic-api-key`), shared by the Anthropic API provider and Claude Code's API-key sign-in. Never written to settings.json, never sent to the webview. In Rust it travels as `llm::Secret`, whose `Debug` prints `Secret(***)`.
- Session instructions and templates: `<app_config>/instructions.json` (`instructions::InstructionStore`), written atomically under a mutex (`store::write_atomic`). A missing file starts with the five starter templates. One that doesn't parse is renamed to `instructions.json.bad` (then `.bad.1`, …; `store::load_json`) rather than overwritten, because it holds the user's writing. Projects are keyed by root path, and `""` is the session with no project open. The frontend saves edits 500 ms after typing stops (`src/lib/saver.ts`) and flushes before switching projects.
- Local runtime and models: `<app_data>/local/{runtime,models,downloads}`, server log at `local/llama-server.log`. Downloads resume through `.part` files and HTTP Range requests. Runtime installs extract into a staging dir, then swap it in.
- Sessions: `<app_data>/sessions/` (`sessions::SessionStore`). `workspace.json` lists each window's tabs and its active tab. `tabs/<id>.json` holds one tab's root, title, draft and its last `HISTORY_LEN` (5) analyses, newest first (`Snapshot`, with its checks, `checksTotal` and `checksFaults`). A closed tab is any tab file no window lists, so there's no closed list to drift; *Recently closed* sorts by `closedAt`, else `updatedAt`. Writes are atomic (`store::write_atomic`). A file that doesn't parse is kept as `.bad`, `.bad.1`, … (`store::load_json`, never replacing an earlier copy) and skipped; a file that can't be read is reported and never overwritten. One `std` mutex guards the workspace and a cache of the tabs read so far, held only for file I/O. The frontend saves drafts 500 ms after typing stops (`createSaver`, keyed by tab id) and flushes before switching tabs and on `pagehide`.
- Usage ledger: `<app_data>/usage.json` (`usage::UsageLedger`): hourly UTC buckets keyed by (hour, root, kind, model), kept in memory, written atomically at most every 5 s when changed (a 1 s shell task that also emits `usage-changed`) and on exit, pruned to 90 days on load. A corrupt file is kept as `.bad`; a file that can't be read is never overwritten (that session's usage isn't saved). Estimates are `ceil(chars / 4)` tokens (system + user sent, text received) at list price, marked `estimatedRuns`: a call dropped mid-stream records one from `Meter::drop`, a call that succeeds without usage records one from `finish`, a call that fails without usage records nothing. A run still in flight when the app quits isn't recorded: Tauri exits the process after the `Exit` callback, so `Meter::drop` never runs. Jev (TypeSafe) calls aren't counted. `Meter::drop` records through the ledger's `std` mutex, so the ledger's locks are never held across `.await`. The UI groups buckets by local day (`src/lib/usage.ts`), so "today" follows the user's clock without a time-zone crate.
- Identifier: `app.livespec.desktop` (was `app.livebrainstorm.desktop`). On launch, `migrate::move_app_dirs` renames the old folder into place when the new one is missing or empty (copy fallback, old kept) and `secrets::migrate_from_old_service` copies the two keychain entries. Neither deletes anything or fails the launch. The window-state plugin reads its file before `setup`, so window positions may reset once.
- Upgrade: on the first launch of the tabs build (`WindowView.fresh`), the drafts the old build kept in `localStorage` (`livebrainstorm.draft.<root>`, with `none` for no project, and `livebrainstorm.lastProject`) become tabs through `import_legacy_drafts`, which runs once. The keys are removed only after it succeeds.
- Frontend: download progress lives in a module-level store (`src/lib/downloads.ts`, `useSyncExternalStore`) so it survives closing Settings.
- Sidebar: hidden or shown per window, in `localStorage` (`livespec.sidebar.<windowId>`: `"1"` hidden, `"0"` shown), read and written inside `try`/`catch`. Without a stored choice, a window narrower than 1,100 px starts with it hidden.

## Cross-language contracts (no codegen; keep in sync by hand)

- **IPC types:** `src/lib/ipc.ts` mirrors the serde types in `src-tauri/src/commands.rs` and `livespec-core` (`settings.rs`, `project/brief.rs`, `local/`). Serde uses `rename_all = "camelCase"`. Enums are internally tagged (`UiEvent` on `type`, `ProviderSettings` on `kind`), and `LocalStatus` / `ModelState` use `#[serde(flatten)]`.
- **Sections:** `sections::CATALOGUE` / `DEFAULT_SECTIONS` / `heading_id` in `crates/livespec-core/src/sections.rs` ↔ `SECTIONS` / `DEFAULT_SECTIONS` / the heading regex and `keyFor` in `src/lib/sections.ts`. Ids, order, the default set and the alias table (exact words: conflict(s) and fault(s) → conflicts, gap(s), ambiguity/ambiguities, question(s), intent) must match; both test suites pin them. The parser tolerates `**Conflicts:**`, `### Conflicts with code` and the old build's `## Faults`; the TypeScript side also renders the old `## Directions` (display-only).
- **Settings defaults:** `Settings::default()` in `settings.rs` ↔ `DEFAULTS` in `src/components/SettingsDialog.tsx`, including `fastEffort` / `deepEffort` (`null`) and `auth` (`"login"`). `Effort` serializes lowercase, `ClaudeAuth` camelCase (↔ `Effort` / `ClaudeAuth` in `ipc.ts`). Both are read through `settings::lenient`, so an unknown value falls back to its default instead of resetting the whole file.
- **New IPC command:** `#[tauri::command]` in `commands.rs`, then register it in `generate_handler!` in `src-tauri/src/lib.rs`, then add a wrapper to `api` in `ipc.ts`. App commands need no capability entry. Plugin permissions do: `src-tauri/capabilities/default.json` grants only `core:default` and `dialog:allow-open`.
- **New provider** touches: `ProviderSettings` (`settings.rs`), a module in `llm/` plus an arm in each `match` on `Provider`, `provider::resolve`, `ipc.ts`, `SettingsDialog.tsx`, and `providerLabel` in `src/lib/providerOptions.ts`.

- **Section parsing:** `prompt::section_body` (Rust) mirrors `parseSections` in `src/lib/sections.ts`; change both together.
- **Check events:** `CheckResult` / `Verdict` in `jev/check.rs` ↔ `CheckResult` / `Verdict` in `src/lib/ipc.ts`.
- **Saved checks:** `Snapshot.checksTotal` is the `count` of the last `checking` event (the claims sent to Jev) and `checksFaults` its `total` (all Conflicts; the field keeps its old name), as `Snapshot::apply_check` records them. `snapshotAnalysis` in `src/lib/history.ts` reads fewer checks than that, without `checksStopped`, as a run an edit cut off, and shows "Checks stopped when you edited." Change both together.
- **Session instructions:** `Template` (with `sections`: empty leaves the tab's sections alone) / `ProjectInstructions` / `InstructionsView` in `instructions.rs` ↔ `src/lib/ipc.ts`; `MAX_INSTRUCTION_CHARS` in `prompt.rs` ↔ `src/lib/instructions.ts`.
- **Sessions:** `Snapshot` / `Tab` (with `sections`) / `TabSummary` / `WindowView` / `LegacyDraft` in `sessions/mod.rs` ↔ `src/lib/ipc.ts`. `sessions::first_line` ↔ `firstLine` in `src/lib/tabTitle.ts` (the first non-empty line, trimmed of Unicode White_Space, at most 48 Unicode scalars; TS uses `\p{White_Space}`, not `trim()`, which differs on U+FEFF and U+0085); both test suites pin the same strings.
- **Brief and workspace events:** `brief-status` (`events::BriefStatus { root, state, message }`, `state` lowercase) and `workspace-changed` (`events::WorkspaceChanged { windows }`) in `src-tauri/src/events.rs` ↔ `onBriefStatus` / `onWorkspaceChanged` in `src/lib/events.ts`. Every session command emits `workspace-changed`, listing the windows whose tab list changed; `save_draft` emits it only when the draft's first line changed.
- **Usage:** `UsageBucket` / `UsageKind` in `usage.rs` ↔ `src/lib/ipc.ts`; the `usage-changed` event (`events::USAGE_CHANGED`, no payload, at most once a second, to every window) ↔ `onUsageChanged` in `src/lib/events.ts`. The panel groups the hourly UTC buckets into local days in `src/lib/usage.ts` (`groupByLocalDay`), which always returns the last 30 days.

- **Lanes:** `prompt::section_groups` (Rust) decides which sections each `lane` carries; `src/lib/lanes.ts` joins lane buffers in lane order. `analysis_system(&resolve(&[]), "")` (no instructions) must stay byte-identical to the single-lane prompt (`all_five_sections_is_the_single_lane_prompt`).

## Deliberate decisions to preserve

- **Never handle Claude subscription credentials.** Anthropic only permits subscription OAuth inside Claude Code and claude.ai, so Live Spec only runs the user's own `claude` binary. Don't add a "Sign in with Claude" flow or read Claude Code's token files. The API-key provider is the path for anyone else using Live Spec.
- Live analysis is stateless: each request spawns a fresh `claude -p`. A persistent stream-json session would start faster but would accumulate conversation history. A tab's saved analyses are for the user to browse; they're never sent to the model.
- Every tab or window id from the webview passes `sessions::valid_id` (`^[tw]-[0-9a-f-]{1,40}$`) before it's used, in the command and again in `SessionStore`. A tab id becomes a file name (`tabs/<id>.json`), so this check is what stops path traversal. Anything else is `Precondition("Unknown tab.")`.
- The old build's section names (`Faults`, `Directions`) stay in both parsers so saved notes render; never remove them.
- Model output is rendered only through `MiniMarkdown` (React elements, never `innerHTML`), behind the strict CSP in `tauri.conf.json`.
- The llama.cpp build is pinned (`LLAMA_CPP_BUILD` in `local/runtime.rs`); upgrading is a deliberate one-line change. CPU builds everywhere except macOS, where Metal is built in.
- Prices are pinned in `usage::PRICES` (list $ per million tokens, from the Claude API model table cached 2026-10-06). Updating them is a deliberate one-line change, like `LLAMA_CPP_BUILD`. The CLI aliases map to the newest model of their family, local catalog models cost $0, and any other model is counted with no price ("—", "price unknown for N runs"), never as $0.
- Apps launched from a GUI don't inherit the shell `PATH`. `shell_env::login_shell_path` asks the login shell once, with a 4 s timeout. The result is used both to find `claude` and as the child's `PATH`, because the npm build of Claude Code needs `node`.
- reqwest uses `rustls-tls-native-roots` (the OS certificate store) so corporate TLS-inspecting proxies work.

## Extension points

- Prompts and the section rules: `crates/livespec-core/src/prompt.rs` holds everything the model sees.
- Another local model: add a `ModelSpec` to `crates/livespec-core/src/local/catalog.rs`.
- Ollama / LM Studio: both speak the OpenAI API, so build `OpenAiCompat` with their base URL behind a new provider setting.
- Fuzzier retrieval ("payments" finding `billing/`): replace the body of `project::retrieve` with embeddings and keep its signature.
- GPU builds on Windows/Linux: change the asset suffix in `local/runtime.rs::asset_name`.
- Starter templates: `STARTERS` in `crates/livespec-core/src/instructions.rs` (text plus a section set). Existing users get new ones through *Restore starter templates*.
- Another section: add a `SectionSpec` to `sections::CATALOGUE` and a matching entry to `SECTIONS` in `src/lib/sections.ts`; the prompt, lanes, picker and parser follow.
